# 文件回放与串口回放

## 文件回放

“文件回放”位于“串口回放”上方。选择原始 `ts,len,hexStr` CSV后，可以直接播放、暂停、继续、停止、调速并查看定位结果，不连接、发送或占用串口。回放使用独立的Model、最新位置缓存与生产Localization算法；现有真实串口可以继续后台采集，但文件回放与实时定位实验不能同时推进。

新实验保存CSV时，同目录同时生成 `<CSV文件名>.session.json`。其中保存本轮观察源、起始节点编号表、有效距离、位置缓存，以及开始、阶段切换、结束与保存的成功/失败记录。操作以接收块数 `afterChunks` 和电脑时间 `at_ms` 定位；设备命令只作为审计信息，不在文件回放中再次执行。保存两份文件任一失败时保留原始记录，允许重试。

带有效操作记录的新文件默认“自动重放操作”，按原接收块边界恢复阶段与惯导原点。播放倍速只改变观看速度；算法的一秒窗口、矩阵有效期和位置年龄均使用记录时钟，暂停后不会因真实时间经过而将数据标过期。回放结束保留最后定位结果；关闭文件返回实时定位。

旧CSV没有操作记录时仍可直接回放，并手动进入初始位置/位置修正，不能恢复未记录的实际按钮时间。旧文件若也缺少连接时的二进制编号表，使用仍可解析的POS/LOC；不会猜测二进制编号对应哪个节点。文件回放默认保留原始位置、距离及时间质量条件，不改变clock_ready或compat_usable。可在停止状态选择“跳过时钟检查”，仅为该文件的离线Localization实例放宽时钟资格；合法坐标、双端时间差、启动周期、来源代次和顺序校验仍生效，原始字段不改写。播放和暂停期间不能切换此选项，改变后清空原结果重放；定位页始终标记该状态。

旧记录若使用人工推定的阶段操作，操作文件应明确标记assumedOperations，界面显示“推定阶段操作”，不将假设时间冒充实际按钮记录。浏览器回放复用同一套FileReplay、定位算法与renderer，浏览器适配层只替换桌面IPC传输；不再播放另一套每秒轨迹快照。 浏览器桥由主工程 `tools/studio_replay_web.cjs` 提供，直接服务软件原renderer资源；同一CSV、起始状态、阶段操作和离线选项下，浏览器与桌面使用同一生产引擎，窗口时间、轨迹和矩阵来自同一类快照。

## 串口回放

“串口回放”保留独立发送功能：选择三列CSV，选择并连接发送串口，然后按CSV时间间隔连续发送至结束。发送不选择、重置或推进定位状态，也不读取操作日志；历史`.session.jsonl`、新`.session.json`和完整性`.meta.json`均不影响发送。

每次最多写512字节，等待write/drain并受8N1波特率约束。暂停保留当前块剩余字节，停止取消剩余字节；整块发完才累计块数和字节数。倍速仅影响块间时间，不突破串口吞吐。

两类回放分别保存最多10条成功加载历史，均默认从设置中的实验保存目录选择CSV。取消选择、损坏或已删除文件不会加入历史；播放和暂停期间不能更换文件。

## 2026-11-01 位置协议 v2

实时采集、文件回放及浏览器共享入口同时支持旧版v1和新版v2。新版POS/LOC使用 `quality=receive time_basis=packet_ms`，没有旧 `clock_ready` 和精确 `error_us`；`compat_usable=1` 且坐标、会话、时间范围合法时，默认按“广播包毫秒级近似对齐”计算，不需要勾选跳过时钟检查。该开关不能放行非法或不可用的v2数据；严格对齐模式拒绝v2近似。旧v1及历史文件保留原规则。录制的原始CSV及操作文件不改写协议标记，缓存/实验初始位置会保存版本和时间依据。
