# UWB Studio

用于 ESP32-C6 / STM32 广播测距节点的本地 Electron 工作台。默认使用真实串口，不装载演示距离。

## 运行

- Windows 免安装程序：`release/UWB-Studio-1.4.3-x64.exe`。也可以使用 `release/win-unpacked/UWB Studio.exe`。
- 源码运行：在本目录执行 `npm ci`、`npm start`。
- 打包：`npm run dist`。

## 日常使用

1. 接好设备，点击“一键连接”。应用优先选择已识别的 ESP 和 STM 数据口，不会自动连接 PWLINK 调试器或虚拟串口；也可“扫描串口”后手动选择，配置波特率和 UTF-8/GBK。默认115200，STM自动用GBK解析旧中文日志。
2. 等待识别RAC。无监听能力的当前广播基线只显示“启动广播”和“停止”，不提供监听/定位模式入口；USB启动使用 `swarm start [session]`，停止使用 `swarm stop`。声明 `monitor=1` 的新分支固件才显示“广播测距 / 纯监听”目标下拉和“启动 / 切换”；选择本身不发送启动命令。需要批量按各口模式启动时，选择“USB已连接节点”并点“全部开始”。需要空中广播控制时，选择“无线全网”及一个非监听网关。只给网关发 `broadcastsend swarm start <随机请求号>`，其他节点通过UWB接收。全网启动同时开启节点的USB结果输出。
3. “无线全网”下“全部停止”发送对应stop广播，纯监听节点不会接收执行空中控制；“USB已连接节点”下逐口发送 `swarm stop` 并等待确认。只有带本次请求号的真实设备ACK才计入无线确认；未确认节点仍显示未确认。尚未被发现的无线节点数量未知，不能由几个ACK证明所有设备均已执行。
4. 目标模式与设备报告的实际模式分别显示。写串口成功只代表发送成功；应用在本次有界状态查询后确认实际模式，失败或超时明确显示，不改变为假成功。断开重连只查询和协商数据格式，不自动启动测距。
5. 主页面同屏显示每个串口自己的无向节点对矩阵。仅右上三角显示距离，对角线显示“—”，仅左下三角用主题色块遮住；所有节点对从电脑收到最后一条有效距离起，连续3秒无新有效距离才显示“—”。串口`-1`仅保存到原始记录及CSV，不清空矩阵、不刷新接收计时、不追加距离历史。此规则同样适用于第三方距离和旧固件；固件测量年龄不作为UI计时起点。新固件在节点本机根据广播时间戳重建其他节点之间的距离；应用不从其他串口补值、不镜像平均。每卡独立暂停显示，后台采集继续。“汇总查看”也按当前终端选中的观察串口展示，不合并覆盖不同观察者。
6. 点击已连接节点可查看该设备独立观测的节点对、接收年龄和配置。周期50–500ms，运行时按钮明确为“停止并应用”；修改后保持停止，需要再次启动。数据流开关控制USB输出，不等于停止空中测距。
7. 每个串口拥有独立终端、历史和筛选。暂停只冻结显示，采集和原始记录继续；清空只清显示。快捷按钮使用已有固件命令，有参数模板时先填入输入框并选中占位符，补全再发。

## 默认快捷指令

| 按钮 | 固件现有命令 | 条件 |
| --- | --- | --- |
| 节点信息 | `swarm info` | 地址及二进制回传能力，连接时自动查询一次 |
| 矩阵快照 | `swarm snapshot` | 恢复编号表和仍有效结果，不刷新已有测量年龄或历史 |
| 节点状态 | `swarm status` | 新模块状态及错误计数 |
| 邻居观测 | `swarm neighbors` | 本机距离快照 |
| 本机地址 | `racaddr` | 旧业务指令，广播运行中可能返回busy |
| 开启/关闭数据 | `swarm stream on` / `off` | 仅改变USB输出 |
| 广播测距启动 | `swarm broadcast start` | 模式按钮经USB控制；旧固件回退 `swarm start` |
| 纯监听启动 | `swarm monitor start` | 仅INFO声明 `monitor=1` 的固件；旧固件禁用快捷入口 |
| 停止本机测距 | `swarm stop` | 仅作用于所选串口 |
| 邻居发现/列表 | `neighbordiscover` / `neighborlist` | 先停广播，使用旧协议 |
| 芯片识别 | `readreg 0` | 先停广播，读取DW1000 DEV_ID |
| 单次测距模板 | `range <目标地址>` | 填参数，先停广播 |
| 广播消息模板 | `broadcastsend <消息内容>` | 填参数，普通广播不执行远端命令 |
| 全部命令 | `help` | 以当前设备实际回显为准 |

设置中可修改、添加和删除快捷命令。升级仅替换完全匹配旧默认标签和命令的列表，用户自定义不会被追加或覆盖。新旧射频模式互斥，busy和参数错误在终端原样呈现，不伪造成功。

## 记录与性能

默认记录位置为“文档/UWB Studio/recordings/启动时间”。每口`.raw`保存原始字节，`observations.csv`只保存通过校验的机器测量记录；可另存CSV、选中串口原始记录和终端文本。磁盘错误/队列丢弃单独可见，不默默覆盖。

采集、解析和文件写入放在独立Electron utility进程，渲染器无Node权限。串口原生异常不会直接带崩主窗口。原型实测曾发现Electron45在worker_threads中打开串口会原生崩溃，因此最终改为独立进程；没有把空界面测试当作连接成功。

界面10Hz合并快照，终端只传增量，每口显示最多500行并复用DOM；后台终端保留2000行供文本导出，完整原始记录独立保存。每条边保留最多600个历史采样，图表有断点，不补造缺失数据；串口输入、写命令和文件背压均有上限。连接后仅查询一次 `swarm info`；检测支持紧凑回传则切换二进制，旧固件超时后回退查询一次状态。没有每2秒自动完整状态轮询。浅色/深色/系统主题；下拉框采用280ms带回弹的展开动画、选择回弹和收起过渡，支持键盘及系统“减少动态效果”。高频距离更新不触发布局弹跳。

采集目录在主进程启动子进程之前创建，避免首次运行打开`acquisition.log`发生ENOENT。日志流的异步文件错误只报告一次，保留在界面记录状态中，不触发未捕获异常弹窗。全新目录启动及日志路径不可写的真实Electron回归已完成。

全网广播控制为了覆盖标准/扩展PHR节点，会短暂切换网关接收模式并暂停其测距发送约4.6秒；这是界面明确显示的控制过渡，不能当作稳态测距间隔。结束恢复实际射频配置。仅连接一台网关USB时，新固件也能上报该网关独立重建的邻居间距离；缺少双方时间戳时保留未知。其他观察节点的独立结果仍须从其自身数据口接收。

## 验证摘要

已完成两ESP与一STM的实际串口连接、单网关无线启停、真实ACK、逐口独立矩阵、终端、复制、记录导出及节点周期配置验证；便携程序实际启动和全新日志目录创建正常。1.2.0最终包另通过真实三口广播/监听切换及USB混合控制；接入独立供电的第四STM后，监听口在四节点矩阵中收到三组广播节点间距离，自身三边保持未知。最终只读GUI检查没有启停节点，详见 `docs/VALIDATION.md`。

正式程序默认读取真实串口。本次开发用临时外部脚本进行模型、模拟串口和隔离界面检查，没有恢复先前移出的测试目录或增加测试专用依赖。隔离界面截图明确使用“示例串口”，不能作为硬件测距证据；本次实机验证由主工程单独记录。

## 紧凑 USB 回传

新固件连接后回复 `@SWARM_INFO`，应用据此识别本串口观察者并请求 `swarm format binary`。正常断开前发送 `swarm format text`；设备上电默认文本，手动串口也可恢复文本。`swarm snapshot` 用于丢批或编号表恢复。

二进制与文字先按字节分帧，二进制不经过UTF-8/GBK解码。编码为 `0 + COBS(frame) + 0`，frame为版本、类型、16位批次序号、16位编号表版本、载荷和CRC16-CCITT-FALSE。完整编号表中每项为1字节编号＋4字节RAC，0号表示INFO中的本机；每条距离为两个编号＋float32米，合计6字节。MAP/RESET/DATA/SNAPSHOT均校验长度、版本、CRC、序号及节点编号。出错撤销编号表解释资格并有界请求恢复；已收到的有效距离继续按原电脑接收时刻3秒到期，绝不猜测编号映射。

CSV列为 `host_time,port,node_a,node_b,distance_m,record_type`，时间是电脑接收时间；`record_type` 区分measurement/snapshot，快照不重复进入距离历史。二进制测量不逐条刷终端，文字命令/响应/诊断照常显示，原始混合字节保持完整记录。两次相同数值的DATA仍是两次真实新测量。界面历史按“串口＋节点对”选择，后台仅向渲染器增量传输新历史点，避免满容量时反复复制整份历史。

## 广播测距与纯监听（1.2.0）

- 广播测距参与SRv2广播并计算节点间距离；纯监听仅接收现有广播、重建其他广播节点之间的距离，不发送UWB帧。监听者到其他节点自身的距离没有双向时间戳证据时保持“—”。
- 新固件INFO声明 `monitor=1` 和 `mode=stopped|broadcast|monitor|fault`。广播和监听时 `active=1`，界面按mode显示实际角色，不能用active推断一定在发射。旧固件未声明能力时，仅允许广播测距。
- 每口目标下拉使用原有Q弹组件，按“启动 / 切换”才执行。设备模式改变、断开或收到RESET不主动清除矩阵，也不延长已有结果；所有边仍按最后有效接收时刻3秒到期。历史和CSV继续保留，设备身份变更才清除原会话。
- “USB已连接节点”按各口各自选择的目标模式启动，并逐口确认；“无线全网”只控制广播模式。正在纯监听或故障的串口不能做空中网关，已知纯监听节点不纳入空中ACK预期。监听节点请用USB启停。
- 单节点及全局控制互斥等待回执，最迟约6.5秒结束本口确认。250ms和1200ms各进行一次有界状态复查；没有常态轮询。忙或失败候选保留实际模式，经复查仍不匹配才报告失败，暂时收到旧模式不会立即判错。故障模式仍可发送停止恢复。

应用新增的窄接口为 `setMode({path,mode})` 选择目标、`nodeControl({path,action})` 执行；只接受广播/监听目标和start/stop动作，主进程校验来源及参数，采集进程再次检查连接和能力。界面不接收原始串口字节。


## 自动图被动定位接入（1.4.0）

INFO声明`passive=1 passive_dim=2 passive_graph=1 passive_max_nodes=20`的ESP使用自动图定位：自动发现广播节点，并在默认1000ms有效窗口内使用可观测图解算，不需要选择固定四节点或手动输入布局。旧1.3固件仍识别为固定四节点版本，旧STM只使用其已声明能力。尚未收到有效自身距离或3秒内无有效更新时显示“—”；其他广播节点间的测距继续独立更新。界面版本不代表定位精度或持续性验收已通过。

- 每口卡片分别显示当前矩阵自身有效距离数，以及带接收时间的最近设备图统计：发现节点、联合节点/边、新鲜证据边、有效自身节点和连通分量。3秒后标记状态待刷新；只在连接或本地命令后有界查询，不周期轮询。
- 终端内置自身状态、开启/关闭、1000ms窗口、高度差、时间戳证据六条快捷；含参数只填入输入框。新UI不再提供固定节点组、单节点坐标或手动布局的默认快捷。用户保存过的这些命令不删除，在自动图固件上禁用并说明原因。
- 被动配置和查询始终只发当前USB串口，兼容前缀不绕过检查，即使勾选“发全部”也不误发旧设备；禁止通过空中全网控制配置监听定位。
- 每口矩阵、历史及CSV相互独立，电脑不推算或跨口补数。六字节二进制距离协议及-1不变；1.4.2所有距离统一使用电脑有效接收时间3秒超时，串口-1仅记录而不改变UI。对角线“—”、下三角遮罩、浅深主题和下拉动画保持现状。

两平台固件能力以各设备实际INFO为准。本阶段STM固件保持原状；自动图算法的编译及实测证据见ESP工程中文验证报告。

## 广播基线兼容（1.4.3）

连接只查询身份、能力和状态，不启动UWB发射；缺少 `monitor=1` 一律按仅广播固件处理。模式下拉及自身定位提示隐藏，保存的监听/定位快捷指令禁用但不删除。快捷与手动命令共用完整行能力检查，支持 `uwb:`、`stm:`、`stm32:`、`esp:`、`esp32:`、中文冒号和大小写；不存在前缀绕过。显式广播启动快捷指令在旧固件自动转换为 `swarm start`，所有本地启停经采集进程的有界状态确认，写入成功仅显示等待回执，不能当作节点已启停。新监听固件的模式切换、定位统计和快捷指令继续按能力开启。
